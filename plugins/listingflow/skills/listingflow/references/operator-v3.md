# 事实核对与运营交付 v3

适用于新任务。旧 v1/v2 任务保持原门禁和原导出格式，不能原地改写版本号来获得新版能力。以下数据全部由助手整理，不让运营填写 JSON，不增加运营的必填项。v3 不代表已核验最新平台政策，也不保证自动识别所有语义错误。

## 一次输入与中文交付

必要输入仍是 SKU、站点和授权资料路径。可选偏好缺失采用默认值，不展开问卷。

交付先用一两句话说明“这是哪款、哪站、草稿还是正式版、还有哪些产品问题”。具体列出最多三个最需要运营回应的问题；剩余问题完整保留表内。助手能从已有资料补证据、改语言、补条件的，先自行解决，不推给运营。

普通请求展示标题、规格、五点、五组问答、详情和双 Excel；如用户偏好只要文件则不重复长文。规则配置由规则负责人处理，不能与产品事实疑问混成“27处文案违规”。不得用总分、通过率或词库未命中数量证明“文案很好”。

## 核对顺序

1. 先辨认 SKU、地区、版本与实际销售配置。旧稿可能是旧版本，不自动授予权威性。
2. 对产品信息表、参数表、说明书和必要实物图建立字段对照。信息表的一处重量冲突不影响其他有依据字段继续使用。
3. 说明书重点读供电、按钮、启动默认值、计时触发/重置、清洁、包装、安全条件。相关图片/PDF 页实际查看并 `observe`，不能只引用图片占位符或“已看图”一句话。
4. 各已发现候选值进入 reconciliation，不仅记录最后选中的数值。来源明确区分物理/电子、产品/包装、档位/公差；不同含义拆成不同字段。
5. 矛盾无权威版本依据时不擅自裁决。非必要尺寸、重量等可不写并保留待办；影响身份、供电安全、核心用途或关键限制时先澄清，不能通过标为非关键绕过。
6. 找不到某个事实的直接依据，就删除该断言或保留问题，不引用看起来有关的段落充数。

“role=manual”是已判定适用于该产品的说明书；不适用版本可标 irrelevant，但必须说明身份与版本排除依据。“reviewed=true”表示确实检查过所需范围，不是解析成功。适用说明书的视觉页须有 visual 观察；无法读清不能冻结成已核对。

## 冻结数据扩展

沿用 contracts.md 的事实结构，新增：

```json
{
  "source_review": {
    "S0001": {"role": "primary", "reviewed": true, "reason": "已核对本SKU信息表的供电及包装字段。"}
  },
  "reconciliation": [
    {
      "field": "battery_configuration",
      "status": "adopted",
      "fact_ids": ["F1"],
      "critical": true,
      "candidates": [
        {"source_id": "S0001:U36", "value": "USB插电，无内置电池", "quote": "USB插电（不带电池）"}
      ],
      "reason": "来源直接写明无电池，电压与线长不作为此声明的替代证据。",
      "action": "文案保留持续插电条件。",
      "owner": "文案助手"
    }
  ]
}
```

上例只展示格式，禁止将编号、值或结论移植到未核对产品。

- source_review 覆盖所有登记文件，role 为 primary/manual/image/reference/irrelevant；reason 用中文写实际检查或排除范围。
- reconciliation 按 field 唯一，每个已确认事实恰好出现在一个 adopted 字段；field 必须与事实字段相同。
- 自定义英文 field 应另外填写中文 label，便于运营报告展示；常见产品字段已有中文映射。label 只用于显示，不改变事实字段身份。
- candidates 保存各来源的候选值、原文和实际定位；视觉摘录另带 observation_id。无需把整个工作簿复制进来。
- adopted 需候选证据覆盖所采用事实的全部 sources。status=omitted 或 pending 的字段不可同时进入 confirmed facts。
- omitted 表示本版明确不写；pending 表示仍需后续核实但本版同样不写。这两者不能悄悄进入文案。
- critical=true 的字段不能悬而未决地冻结，并自动要求进入 brief.critical_fact_ids。已知安全/使用前提与重置条件应作为独立事实保留。
- reason、action、owner 必须具体，不能都填“已核对”；人工决策仍只记真实用户原话，不冒充审批。

程序能强制结构和引用一致性，不能证明没有漏读文件或遗漏候选值。必须实际交叉阅读；把整份来源标为 irrelevant 不得成为规避核对的捷径。

## 逐条声明审核

每个 review.blocks[path] 新增 claims，覆盖该块全部文字；多个断言拆分为连续原文片段，允许共享关联事实，但禁止一个长句挂一批事实后直接整体 PASS。

```json
{
  "status": "PASS",
  "fact_ids": ["F1"],
  "reason": "信息表明确写明不带电池；本句未扩大为兼容任意电源。",
  "claims": [
    {"text": "No built-in battery.", "fact_ids": ["F1"], "status": "PASS",
     "reason": "原文直接注明不带电池，属于翻译，不是从USB接口推断。"}
  ]
}
```

claims 中每项状态为 PASS/FAIL/NEEDS_REVIEW/NOT_CHECKED；任何子声明未通过，整块不得 PASS。所有原句文字须覆盖，所有引用事实须有解释。reason 对应“该片段所断言的事情”，不是“无医疗词”“语法正确”等无关结论。

fact_evidence 仍对每个使用的事实保存真实原文，不自行翻译 quote。原文与断言的支持关系要检查否定、条件、数量、单位、版本和作用范围；摘录不能截掉改变含义的前后文。

review.conditions 的键恰好覆盖 brief.critical_fact_ids，每项为 `{"path":"实际块路径","quote":"本版保留条件的原句","reason":"中文解释如何保留原条件"}`。图片分类 PASS 须列出实际 visual 的 observation_ids；没有观察记录不得声称通过。图片事实核查与图片版权归属是不同问题，后者不因看图而得到确认。

程序附加有限的电池、绑带、独立控制、计时重置、实物/电子说明书和公差单位提示。提示不是任意英德句子的语义判定器；未触发不等于已证明。合理误报应检查原文并改进规则或保留具体说明，不批量改 PASS，不通过删关键条件消除告警。

## 文案质量标准

- 标题帮助买家认出品类、主要区别与必要供电条件，不机械堆满字符。
- 每个五点围绕一个购买问题，顺序按产品价值确定。先清楚说功能带来的实际选择，再给必要参数；不把所有档位、公差塞入第一条。
- 完整数值集中到规格，关键限制在相关声明旁保留。不要为了减少重复，把会改变承诺含义的条件移到买家难以发现的地方。
- 详情补充使用过程、配置和维护边界，不把五点换句式重复一遍。
- 问答优先回答供电、电池、控制是否独立、定时、清洁、随附物等真实疑问，只选有依据的五组，不自创未知功能凑数。
- 可以解释已证实功能的直接用途，但不得创造“缓解眼疲劳、改善睡眠、治疗干眼”等未证实功效。
- 美国温度可用华氏；温度本值乘9/5加32，温差仅乘9/5。来源若为±5°C，换算为±9°F，不舍弃公差。精度不能超过来源支撑。
- 中文审核理由说清“这段让买家知道什么、是否有多余或缺失信息”，不要用重复的“自然流畅”充数。

## 运营自查表

默认可见页：

1. 审核结论：SKU、站点、版本、带时区的检查时间；分开显示“文案检查”与“发布前确认”，不把前者没有问题当作后者获批。四类摘要可点击跳转。当前优先待办显示下一步、负责方与完成条件；超过三项时明确还有几项并链接完整清单，不隐藏其余问题。
2. 违禁词自查表：上下文语义审核及适用违禁词库逐词扫描。逐项显示检查问题、结果、一句话判断、原句、完整依据和建议。
3. 侵权词自查表：品牌、IP角色、赛事、奢侈品牌分别审核，再展示适用侵权词库逐词扫描。文字未出现名称不能证明图片、外观或商品权利已清查。
4. 本地化自查表：标题、五点、单位与实际配置、拼写语气、搜索数据分别核查。自然表达不等于取得了当地搜索量验证。
5. 文案合规自查表：词频、夸大词、跨类目词、医疗暗示、侵权词逐项核对；附客观词频及公司长度规则检查。没有统一词频阈值可以替代语义判断。
6. 处理清单：仅展示当前待办，给出原句或影响、处理建议、负责方和完成条件。蓝色区域可填意见、确认人、日期、反馈状态；不提供“填了就自动批准”的操作。
7. 已处理与可选：非关键、未进入已采用事实且有同版逐句审核的未采用字段，显示“本版不采用，无需补填”，保留差异和以后补写的条件；资料本身未被判为已解决。审核缺失、过期、关键字段或仍进入已采用事实的冲突不能如此归类。旧任务保留原搜索数据提示；新任务关键词调研是助手默认工作，受限来源单独列调研待办，不要求运营上传关键词文件。
8. 内容检查、来源依据、规则与范围：保留逐句事实核对、字段冲突、公司规则审批和未检查资料范围。

`✓ 已核对`只表示本项记录范围内的语义核查；`✓ 未命中（精确匹配）`只表示当前词库扫描。`✗ 需修改`、`待确认`、`未检查`分开展示。未批准公司规则不阻止逐词草稿自查，但不能据此给出正式批准结论。不用全绿、总分或通过率包装未完成的核查。

版本页默认隐藏但保留；完整检查和审计保留在同批 export.json 和任务历史。草稿始终标明状态；已核对条目不再旁列“阻断”制造误读。新布局标记为 `operator-overview-v1`，旧批次按原布局逐格回读，不覆盖旧文件，也不改变任务规则或审核门禁。

Excel 是导出快照，系统结果锁定仅用于防止误改，不是访问权限或身份认证；蓝色反馈单元格保持可填。填表、选择“已回复”都不会修改任务状态或替代批准。运营只需看首页、处理自己负责的事项、审阅当前文案；回复“尺寸继续不写”等反馈不会自动获得规则或图片授权。回传具体事项后由助手重新核对，发生文案修改则新版本重审，未改文案仅换报告布局不虚增文案版本。

## 四类专项审核

`prepare --kind review` 在 v3 中提供 `operator_checklist`。每项包含 `status`、`paths`、`examples`、`reason`、`action`；全部由助手在实际检查后填写。项目键以 `scripts/lf_checklist.py` 的 ITEMS 为准，覆盖四类16项，不让运营填写技术结构。

- `paths` 明确本次审阅的成品段落；标题项至少覆盖标题，五点项覆盖全部五点，其他文本语义项覆盖所有成品段落与规格名。规格名使用 `specs.0.name` 等路径，可直接引用该栏目名作为例证。
- `examples` 为 `{"path":"title","quote":"当前文案中真实存在的片段"}` 数组。PASS/FAIL 必须有原句例证，不能引用旧版本或编造命中。没有出现风险词时，例证用于定位被审阅内容，中文理由另说明实际排查范围，例证本身不证明“全文不存在”。
- `reason` 回答本项具体问题；`action` 写实际处理或“无需修改”。品牌、IP、赛事、奢侈品分别下结论，不能四行复用“未发现医疗词”。
- 医疗词须区分功效营销与说明书安全警示，不能见到 doctor/disease 就机械判违规，也不能凭一项词库未命中直接判通过。
- `ip.visual` 单列商品图片与外观权利核验边界；看过图不等于有授权。没有权利材料时标待确认/未检查，作为专项提示，不冒充文本词库命中。
- 新任务先按 [关键词自动调研](keyword-research.md) 采集下拉建议、竞品样本和 PLA 推荐词；`local.search_data` 由绑定本版的实际记录派生。三类均已取得才表示来源完整；部分受限明示各自状态，不把所有来源概括为未验证。缺失调研步骤会阻断正式批准；如实记录的访问受限不妨碍交付草稿，也不冒充搜索量核验。
- `ip.visual` 若标 PASS，仍须额外提供 `evidence` 数组，每项含任务真实来源 `source_id`、真实摘录 `quote`、明确适用 `scope`，图片还需 `observation_id`。旧任务 `local.search_data` 的证据契约保持不变；新任务改用同版 `research_hash` 与三类采集记录。来源存在不等于授权效力已得到法律确认，仍须实际核对摘录是否支持结论。
- 新任务冻结 `checklist_version=1`。旧v3任务不自动改变门禁或导出布局；用户明确要求升级自查时，补交含 `operator_checklist` 的真实审核后启用，并记录于任务新修订。缺项只在已启用新版检查的任务中阻断正式导出。v1/v2与历史导出保持不变。

## 本次真实案例的回归要求

至少检查：单字段重量冲突不排除其他字段；尺寸不同保留候选值及版本疑问；USB参数不证明无电池；电子多语说明书不写成包内实物；15分钟条件包含按键重置；独立控制不能用无医疗宣称作理由；绑带有具体依据；图片PASS必须有观察；配置待确认不冒充违规数量；默认文本与Excel均包含规格和QA。

合成回归测试用于验证程序行为，不能代替真实商品重新生成和运营评审。更新Skill后，不宣称旧101627文案已自动修复或已经正式可用。
